# Atoolkit v9.2 迭代方案：报告出口收口与现象分层（垃圾洞治理）

日期：2026-08-12
修订：v9.2.1 二次审核修订（2026-08-12）——审核结论见 §8；代码引用已逐条复核。

## 1. 背景与实证

批量 Skill Mode 实跑（penetration_jw、byteDance 等工作区）反馈：最终报告混入垃圾洞与"威胁当漏洞"，每轮都需人工复测才能出报告。对两个工作区的只读审计结论：

- `byteDance/runs/volcengine-console-20260809/final_report.md`：漏洞4「signin CORS Preflight 任意 Origin 反射 + Credentials」（报告自述浏览器无法读取跨域响应，即无已证影响）；漏洞5「encCerts 未认证泄露 RSA1_5 弱算法公钥」（严重度写 P4，超出 schema 允许的 P1-P3）。该 run **无 finding.json、无 run_manifest、state/ 为空**——纯手写 Markdown，未走任何管线。
- `penetration_jw/.../run_001/final_report.md`：「TLS 证书过期」「混合内容」标 P3 已证实；后端 502 宕机轮次无真实 API 测试。
- `penetration_jw/qyzzglxt_zshl` 的 finding.json 为旧精简 schema（无 vuln_class/claim.kind/impact_claims），按规约只能迁移为候选。

### 根因分层（按实跑影响排序）

1. **裸 Skill 路径无代码门（主根因）**。Guardian、证明合同、finalizer 全部未接线；agent 手写 `final_report.md` 仅被 `skill_runtime` 记为 `reserved_artifact_violations`（report_ready=false），文件原样保留，人工一拿走即绕过全部门。
2. **结构性盲区**。弱加密/公钥/配置泄露类不在任何拦截词表（`enforce.py:40-45`、`validate.py:88-105` 均无「弱算法/公钥/RSA/JWT」条目）；generic family 只要 `response_differential` + control/exploit 包即 accepted（`validate.py:1030-1033`），全程没有"必须证明安全后果"的门。
3. **关键词黑名单天然脆弱**。标题子串匹配，改写即绕（「跨域配置不当」不含 "cors"）；且 Skill checkpoint 路径不跑 Guardian（`skill_runtime.py:832` 只调 `collect_structured_findings`）。
4. **假设搭便车**。accepted finding 内部的 hypothesis 级 impact/chain 与未测候选会随正文和缺口附录合法进入最终报告（`render_md.py:207-215`、`:47-83`）。

对照组：同一 CORS 标题若走 `validate_finding` 必被 `SUBMISSION_NOISE_ROOT` 拒（`validate.py:89`，有合同测试钉死）——证明现有黑名单"能拦住"，只是实跑路径没经过它。

## 2. 设计原则

- 回归项目初心：**不限制模型怎么测，只收报告出口；出口由代码把守，不靠模型自觉**。
- 产物物理分层：漏洞报告（已证结果）与观察报告（现象级发现）分离；人工先审最终报告，再审观察报告。
- 新门一律放在所有模式共用层（`validate_finding` / `skill_runtime`），禁止只挂在 Engine 路径。
- 现象降级 ≠ 信息丢弃，也 ≠ 验证失败的洗白通道：只有"证据有效但影响仅达现象级"的 finding 才降级；证据/授权/格式硬校验失败的 finding 仍是 rejection。
- 复用现有机制优先于新造：`demoted` 语义（`enforce.py:52-55`）、`chain_assessment`（`validate.py:766-798`）、`vuln_classes.py` 分类法。

## 3. 修复设计

### 3.1 A：Skill Mode 报告出口收口（根治项）

新增 `python3 -m engine.skill_runtime report --run-dir <run>`：

- **三态语义与 finalizer 严格一致**（不发明第四种行为）：`proof_pass && closure_pass` → `final_report.md`；仅 proof_pass 有已证 finding → `draft_report.md`；proof 失败两者都不留。决策逻辑抽成共享函数，`finalize.py` 与 `skill_runtime report` 同调一个实现。
- 输入仅取 checkpoint 归并后、经完整验证（`validate_finding` + Guardian，见 3.2）通过的 canonical Finding 包；渲染复用 `render_final_report`，保持单一渲染器。
- **手写最终报告处置（quarantine + 代码重渲染）**：checkpoint 与 report 两个时机都检测 `final_report.md` / `draft_report.md` / `observation_report.md` 是否非代码渲染产物；是则移入 `state/quarantine/<name>.agent.<ts>.md`（不删除，可审计、可恢复），再由代码重渲染。
  - 作用：维护 §0.1 已声明的不变量「final_report.md 是 finalizer 保留产物」，保证"第一眼看到的报告必过验证门"。
  - 为什么不是保留+横幅：横幅把未验证声明留在第一眼位置，模型自报的严重度和结论原样保留，正是本次痛点的来源；只记违规（现状）则标志位不在产物上，人工拿到文件时不可见。
  - 为什么是 quarantine 而不是删除：符合项目"证据落盘不销毁"传统；quarantine 内容同时是观察报告的素材来源之一。
- **诚实声明的时序残余缺口**：裸 Direct 模式无 wrapper，agent 可在 report 运行之后再次手写报告，代码物理上防不住。缓解：report 把渲染结果的 sha256 写入 `runtime-status.json` 并打印；人工验真习惯 = 只信与 `runtime-status.json` 记录 hash 一致的报告文件。完全闭合需要 Wrapped Skill。
- **完全裸跑输入**：run 目录零 engine 产物时，report 命令仍可运行——没有可验证 finding 则不产出漏洞报告，观察报告按可验证输入渲染，status 固定 diagnostic。
- checkpoint 的 finding 收集路径补调 `guardian_check_finding`：Guardian 八级门从"仅 Engine/finalizer 路径"补齐到 Skill 路径（Guardian 判定同样遵守 §3.2 三分类，demoted 不算 rejected）。

### 3.2 B：结构化现象分类 + 后果链门（替代纯关键词黑名单）

- **现象分类法落在 `vuln_classes.py`**（代码内常量 + 测试钉死），由 vuln_class/证据结构确定性判定，title 词表仅作辅助：`cors_misconfig / weak_crypto / public_key_disclosure / version_disclosure / missing_security_header / ssl_tls_config / rate_limit_absent / open_redirect_unproven / directory_listing / error_stack / self_xss / public_info_disclosure`。
- **三分类 outcome**：`validate_finding`/`collect` 的输出从 accepted/rejected 两桶改为 **accepted / rejected / observation 三桶**。observation 是独立分类，**绝不进入 rejected 列表**——不触发批原子门（`validate.py:3596-3628`）、不计入 proof_gate reasons、不计入 checkpoint 的 `proof_repair_required`。批原子门对真 rejection 的连坐语义保持不变（防洗白：证据/授权/格式硬失败仍 reject 并连坐）。
- **降级条件**：现象类 finding 证据有效但无已证后果链 → `claim.kind` 归为 `observation`，进观察报告。**升级条件**：现象类 finding 携带 `chain_assessment.status=proven` 且 proof_refs 终止于后果类 impact_claim（`data_read / state_change / code_execution / authorization_bypass / fund_change / trusted_secret_use`）→ 仍可作为 root_finding accepted。复用现有 chain_assessment 机制，不新增字段。
- **收敛现有条件门**：rate-limit/open-redirect 需 chain proven、error-only 需 security_boundary、凭据泄露需跨边界使用（`validate.py:698-763`）统一并入"现象类 + 后果链"同一机制。**行为变化明示**：这些类今天是无链即 rejected（会触发批原子连坐），统一后改为无链即降级 observation——批连坐毒性消失，但需在 CHANGELOG 与测试中明示语义变化。
- 门落 `validate_finding`（Engine/Wrapped/Direct 三模式共用）；Guardian `GARBAGE_TITLE` 保留为 Engine 路径的冗余第二道，其 rejected 命中在三分类下映射为 observation（Guardian L6 `demoted` 语义对齐）。
- 词表扩盲区：弱算法/弱加密/公钥/RSA/JWT/加密套件/证书过期/混合内容等加入现象识别；分类由结构化字段决定，标题改写不再能绕过。

### 3.3 C：双产物分层

- `final_report.md`：仅 `proof_status=confirmed + claim.kind=root_finding` 的漏洞。人工第一眼产物。
- `observations.json`（新增，authoritative 机器真值）：每条 observation 含稳定 id、`phenomenon_class`、endpoint/param、evidence_refs、为何只是现象、可能的链式方向、source session/run；**不携带 P1-P3 严重度**（防止"P2 CORS 观察"继续污染视觉优先级）。observation 永不进 ProjectState finding registry。
- `observation_report.md`（派生人类视图）：只从 `observations.json` 渲染，按 phenomenon_class 分组。范围按本轮评审结论：**只放现象级发现**；finding 内 hypothesis 与未测候选维持现状（随 accepted finding 正文标注渲染 / 进缺口附录），不混入观察报告。
- **跨 Run 升级路径**：后续 run 为某 observation 补出后果链时，走正常 finding 验证（可经 continuation 引用历史证据），accepted 后进入漏洞报告；observation 本身不被"提升"，避免绕过当轮验证。
- 命名取"观察报告"而非"威胁报告"：项目语义中 threat 是 threat-model 编译出的待测假设单元（`threat_model.py`），不是"发现"，避免概念串线。
- 机械接入点（三模式一致）：`observations.json` / `observation_report.md` 加入 finalizer `_DERIVED_RUN_FILES` 快照排除清单；`observation_report.md`（连同 `draft_report.md`）加入 `DIRECT_RESERVED_ARTIFACTS`（手写即 quarantine）。`observations.json` **不加入** reserved 清单：checkpoint 与 report 每轮确定性重写它，手写内容无法存活，加入反而会误 quarantine 代码自写产物。Engine 路径的降级收集点在 `validate_run_artifacts`，由 finalizer 统一渲染。

### 3.4 接线矩阵（现状 → 目标）

| 门 | Engine | Wrapped Skill | Direct Skill |
|---|---|---|---|
| validate_finding 现象三分类门 | 无 → 有 | 无 → 有 | 无 → 有 |
| Guardian（checkpoint 路径） | 有 | 有 | 无 → 有 |
| 手写报告处置 | n/a（finalizer 独占） | 有（wrapper finalize） | 只标记 → quarantine+重渲染（含时序残余声明） |
| 漏洞报告渲染 | finalizer | wrapper→finalizer | 手写 → `skill_runtime report` 独占（三态语义共享） |
| observations.json / 观察报告 | 无 → finalizer 渲染 | 无 → finalizer 渲染 | 无 → `skill_runtime report` 渲染 |

### 3.5 兼容与迁移

- 旧 run 不重渲染、不提升；`run.py audit` 只读口径不变。旧精简 schema finding 仍只迁移为候选。
- AGENTS.md 同步项：§0.1 报告所有权补 observation_report 归属；§1 垃圾洞清单措辞从"默认不报"改为"默认降级观察报告"；§8 Finding 包补现象分类与后果链字段；§11 终态自检补"最终报告 hash 与 runtime-status.json 一致"。

## 4. 非目标与硬边界

- 不限制模型测试和记录现象的自由；分层是产物归属，不是测试约束。
- 不把现象门做成评分/惩罚手段，只做产物分层。
- 不改 `authority_trusted` 语义：diagnostic run 依旧不提交 ProjectState、不声称 verified delivery。
- 不在 prompt 层新增方法论内容（约束密度不增长）；本方案全部落在代码层。
- 降级不得成为验证失败的洗白通道：硬校验（证据存在性/断言/授权范围/格式）失败的 finding 仍是 rejected 并触发批原子门。

## 5. 发布门

1. 合同测试：CORS/弱加密/证书类 finding 无后果链 → 进 observation 桶、不进 final_report、进 observation_report；有 `chain_assessment.status=proven` 且终止于后果类的现象类 → 可 accepted。
2. **三分类隔离**：observation 不触发批原子门、不计入 proof_gate reasons、不计入 `proof_repair_required`；硬校验失败的 finding 仍 rejected 且连坐语义不变。
3. **三态一致性**：同一 run 输入下，`skill_runtime report` 与 finalizer 的 final/draft/none 决策逐字节一致（共享决策函数的回归测试）。
4. checkpoint 路径 Guardian 生效回归；手写 final_report.md 在 checkpoint 与 report 两个时机都被 quarantine 且代码重渲染回归；渲染 hash 写入 `runtime-status.json`。
5. rate-limit/open-redirect/error-only 语义从 rejected → observation 的变化有明示测试；observation 不进 ProjectState finding registry。
6. 三模式（Engine/Wrapped/Direct，含零产物的完全裸跑目录）各跑一遍端到端，产物归属符合 §3.4 矩阵。
7. 全量 pytest、self-check、strict doctor、compileall 通过。

## 6. 实施顺序

1. A：`skill_runtime report`（共享三态决策）+ quarantine（两时机）+ checkpoint 接 Guardian（先根治裸跑出口）。
2. B：`vuln_classes.py` 现象分类 + 三分类 outcome 改造 `validate_finding`/`collect`（含现有条件门收敛与批原子隔离）。
3. C：`observations.json` + `observation_report.md` 渲染接入 finalizer 与 skill_runtime report。
4. AGENTS.md 同步 + 合同测试补齐。

## 8. 二次审核结论（2026-08-12）

代码引用逐条复核属实（`skill_runtime.py:832` 无 Guardian、`:1021-1023` 只标记不处置、`validate.py:88-105` 无弱加密词表、`:3596-3628` 批原子门存在、`enforce.py:40-45` 词表无盲区覆盖）。审核修订四处：

1. **P0 批原子门冲突**：初版未说明降级与 rejected 的关系。若降级实现为 rejection，一个垃圾洞经 `validate.py:3601` 连坐清空整批 confirmed，且 `proof_repair_required` 永久阻塞 report_ready。修订为三分类 outcome（§3.2）。
2. **P0 report 语义跑偏**：初版"report_ready=false 只渲染观察报告"与 finalizer 三态（final/draft/none）矛盾。修订为共享决策函数、三态严格一致（§3.1）。
3. **P1 机器真值载体缺失**：补 `observations.json` authoritative 层与机械接入点清单（§3.3）；observation 不带 P1-P3 严重度；补跨 Run 升级路径。
4. **P1 时序残余诚实化**：quarantine 无法防止 report 之后的再次手写，补 hash 验真习惯与 Wrapped 闭合声明（§3.1）。

### 实施期修订（2026-08-12，v9.2.0 落地）

5. observation 记录增加持久化 `title` 字段（渲染需要）；report 命令会删除"上一次代码渲染、本轮决策已不再生成"的陈旧投影（对齐三态"proof 失败两者都不留"）；手写文件永远走 quarantine 不删除。
6. **顺带修复 pre-existing 缺陷**：Direct init/checkpoint 曾用模型视图覆写 Host 的 `execution-queue.json` 投影（v8.10 遗留），导致任何 checkpoint 之后 `validate_run_artifacts` 必现 `execution_projection_mismatch`、closure 恒失败。已改为只写 Host 投影、模型队列只随 checkpoint 字典返回，并补 checkpoint→validate 一致性回归测试。
